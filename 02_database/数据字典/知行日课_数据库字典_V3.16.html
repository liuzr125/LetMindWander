短文临时 NLS Token 生成与持久化

小程序按需合成（2026-09-20）：系统参数新增约定键 ALIYUN_NLS_TEMPORARY_TOKEN，复用 app_parameter 表，不增加列。由管理员在“系统参数 → 保存 / 更新临时 Token”或“AI 模型与费用 → 语音合成 → 保存 Token 到系统参数”录入；服务端强制 is_secret=1、AES-GCM 加密保存 param_value，列表不返回原文，参数写请求不记入访问日志。

小程序仅调用 POST /api/learning/contents/{id}/speech，不接收或提交 NLS Token。已有 ready 音频优先复用；没有时后端实时读取 state=active 且 del_is=0 的参数，解密后调用 NLS，再上传 OSS、保存媒体地址与内容关联。无有效参数或 Token 被拒绝时明确报错，不回退 AccessKey；更新参数即时生效，重启无需再次录入，但不会延长供应商有效期。删除保持 del_is=1 的软删除规则。

音频保存字段：短文为 content_version.article_audio_asset_id；短文点词词汇（如 glossary:working）为 article_word_glossary.audio_asset_id、audio_voice、audio_generated_at；词条为 pronunciation.asset_id。均关联 media_asset.object_key，tts_usage_log 记录逐次生成结果。保存的是音频资源与关联，不将 Token 放入媒体地址或日志。

批量生成：管理端支持本页多选或当前难度、搜索条件下的全部分页。先读取并确认范围，再输入一次 Token，浏览器串行调用现有单篇接口；已有音频跳过，每篇成功立即上传 OSS 并保存关联。无新增批次表或 Token 字段，沿用下述媒体、版本及逐篇用量日志。

批量 Token 仅保留在当前运行内存，不落库或浏览器存储；本批结束即释放。Token、鉴权、OSS、网络或服务端错误会停止后续请求；单篇文本校验错误记录后继续。停止等待当前请求完成，失败及未处理项可重新输入 Token 继续，成功项不重复提交。页面关闭后不后台执行；已保存音频可刷新恢复，临时进度不持久化。

2026-09-20 · 复用现有表结构，无新增字段或数据库迁移。

管理端 POST /api/admin/content/articles/{contentId}/speech 的 JSON 请求体必须包含 nlsToken。仅本次请求使用，不依赖其他页面试听会话，不回退至 AccessKey 获取 Token。Token 不落库、不写入访问日志、不进入 URL，也不保存到浏览器本地存储；失败后重新输入。

使用服务端已配置的 AppKey、音色与采样率调用 NLS，成功后将 MP3 上传 OSS，再保存以下关联。NLS Token 不提供 OSS 上传权限，OSS 仍需独立的服务端凭据。当前单次正文上限 300 字符，超过时明确拒绝，不截断正文。

表 / 字段保存规则
media_asset.object_key永久对象路径 tts/english_article/{assetId}.mp3；媒体类型 audio/mpeg、purpose=article_audio、state=ready，同时保存字节数和 SHA-256。仅 OSS 上传成功后写入。
content_version.article_audio_asset_id关联 media_asset.id；同时更新 article_audio_voice、article_audio_generated_at，绑定生成时读取的已发布版本。

接口返回 assetId、audioUrl、voice、cached。audioUrl 是媒体服务稳定访问地址，播放时解析 OSS 地址；数据库保存 object_key 而非会过期的签名 URL。刷新列表后由版本关联恢复播放入口；已有同音色 ready 资产则复用。合成或 OSS 上传失败不写入新的短文音频关联。
